A modular Discord character bot with real-time voice. Alice listens to voice chat, tracks who is speaking, answers when she is addressed, and is shy on purpose: whether she takes a lull in the conversation is a probability you can tune, and when she catches only a *mention* of her name she peeks in cautiously — *"...was I being talked about?"*

Personality/inference runs on [Groq](https://console.groq.com) by default (cloud, no local GPU needed, fast, free tier available), with a local Ollama backend for offline dev/testing. The fine-tuned voice model itself is not published (see the note below) — everything that makes her conversational is.

## Architecture

```

  data/alice/         Alice's lore, examples, GIFs, relationship tones (JSON/text)
memory/               SQLite store + in-memory importance-weighted graph
emotion/              Per-user emotion state + intent keyword detection
social/               Discord-user identity registry (father-roleplay, etc.)
reddit/               Fetch (HTTP, no API key), filter/dedupe, rotation
state/                Redis-backed shared state (emotion, GIF cooldown, identity)
metrics/              Prometheus metrics collection
health/               Health check endpoints (/healthz, /ready, /metrics)
templates/            Jinja2 prompt templates
voice/                Voice pipeline (v2.3 - GPT-SoVITS engine + conversation-aware)
  pipeline.py         Main orchestrator — STT → decision → AI → TTS → play
  sink.py             AliceVoiceSink — per-user buffering + Silero VAD
  state.py            Voice state + turn states + speaker tracking
  conversation.py     Rolling conversation history (last 10 utterances)
  turn_detector.py    Sample-based turn completion (7 states)
  response.py         Response decision engine (I1/I2/S1/S2)
  backchannel.py      Brief acknowledgment generation
  soft_phrases.py     Curated name-mention clarifications (static EN+JA pool, no AI round-trip)
  mixer.py            Audio playback with barge-in
  preprocess.py       STT audio preprocessing (noise floor, loudnorm, denoise)
  streaming_source.py Custom AudioSource — accepts PCM while playing
  streaming_tts.py    Sentence-by-sentence TTS streaming
  vad.py              Silero VAD wrapper
  stt.py              Moonshine (fixed-language) + faster-whisper STT
  tts.py              TTS dispatch (GPT-SoVITS primary, Edge-TTS fallback)
  sovits.py           GPT-SoVITS client + auto-managed API server
  readiness.py        Mute-until-ready gate (warmup + fallback decision)
  rvc.py              RVC inference wrapper
  diarize.py          pyannote speaker diarization
  dave_patch.py       discord-ext-voice-recv monkey-patches (DAVE decrypt, plain-frame recovery, per-packet resilience)
  utils.py            ffmpeg finder
```

Adding a **second character** later = a new folder under
`character/data/<name>/` with the same files Alice has. No Python
changes required unless the new character needs new intents/rules.

Adding a **third subreddit** = one entry in `config.REDDIT_SUBREDDITS`
plus one short command in `cogs/reddit_cog.py` following the existing
pattern.

Running **multiple bots** = set `BOT_NAME` prefix for each bot's env vars
(e.g. `ALICE_DISCORD_TOKEN`, `BOB_DISCORD_TOKEN`) and they share the
same codebase with isolated data directories.

## Setup

1. `python -m venv venv` then activate it.
   - CPU: `pip install -r requirements.txt`
   - GPU (CUDA, e.g. GTX 1650 Ti): `pip install -r requirements.txt --index-url https://download.pytorch.org/whl/cu126`
2. Copy `.env.example` to `.env` and fill in real values (see below).
   ```
   AI_BACKEND=groq
   DISCORD_TOKEN=<your bot token>
   GROQ_API_KEY=<from https://console.groq.com/keys>
   OWNER_IDS=<your discord user id>
   ```
   Get `GROQ_API_KEY` from https://console.groq.com/keys (free account,
   no credit card required for the free tier as of writing).
3. **Rotate the Discord bot token before using it.** A bot token *is* the bot's
   account -- `Discord Developer Portal -> your application -> Bot -> Reset Token`
   invalidates the previous one immediately. See "Security Note" at the end of this
   file.
4. First Reddit data pull. This copy ships no post data, so run this once to
   build the pools:
   ```
   python manage.py refresh-reddit
   ```
5. Run locally: `python main.py`
6. Voice (optional): `VOICE_ENABLED=true` plus an engine —
   `VOICE_TTS_ENGINE=sovits` needs the GPT-SoVITS install (auto-started
   and health-checked by the bot), `edge` works anywhere with no local
   server. See **Voice Capabilities** below.
7. Verify the install: run `/voice-status` in a voice channel — it shows
   "Soft Responses" (name-mention clarification replies) and "Diarization"
   (speaker stats if `VOICE_DIARIZE_MODE=detect|address`), plus the torch
   device and CUDA availability.

## Gift Command (`/alice-gift`)

### Overview
Give Alice a gift via interactive modal. Increments per-user gift count, upgrades relationship tier, and generates an in-character reaction.

### Categories
| Category | Label | Description |
|----------|-------|-------------|
| `boko` | Boko-Related | Pajamas, teddy bear, accessories, outfits, companions, care items |
| `alice_accessory` | Alice Accessory | Hair clip, jewelry, scarf |
| `alice_clothing` | Alice Clothing | Sweater, jacket, dress |
| `food_drink` | Food or Drink | Burger, fries, chocolate, tea (dislikes: cheese, tomato, olive oil, anchovies) |
| `letter` | Letter to Alice | Free-write framed as a letter she reads aloud |

### Letter Reading Feature
When category is `letter`, Alice **reads the letter aloud** in chat using *asterisks* for quiet muttering:
```
*reads quietly* "Dear Alice, I l... th-thank you..." *looks down, cheeks red*
Th-thank you. I-I'll keep it close to my heart.
```

### Public Message Format
- **Non-letters**: `@user gave Alice a/an <item>:`
- **Letters**: `@user gave Alice a letter:` (content shown in her reading)

### Modal UX
- **Letter category**: "What does the letter say?" / "Write your letter to Alice..."
- **Other categories**: "What are you giving her?" / "Describe the item..."

### Technical Fix: Groq Empty Reply
The original full prompt (~1700 tokens) exceeded the token budget, causing Groq to return empty. Fixed by:
1. **Minimal gift prompt** (`character/prompt_builder.py::build_gift_prompt`) — ~500 tokens with only essentials (identity, Boko fact, 1 style example, letter-reading instruction)
2. **Increased `GROQ_MAX_TOKENS`** from 300 → 600
3. **Token usage logging** in `ai/groq_client.py` for debugging

## AI Backends

Set `AI_BACKEND` in `.env` to one of `groq`, `shapes`, or `ollama`.
Switching later is a one-line env change -- nothing else in the
codebase needs to change (`ai/__init__.py::get_ai_client()` picks the
client, and `config.INJECT_FULL_CHARACTER_PROMPT` picks the prompt mode
based on which backend is selected).

### Groq (current default, cloud)

Groq is an OpenAI-compatible cloud API -- fast responses, a generous
free tier, no local GPU needed.

```
AI_BACKEND=groq
GROQ_API_KEY=your-groq-api-key
```

Get your key from https://console.groq.com/keys. `GROQ_MODEL` defaults
to `openai/gpt-oss-120b` (the free-tier workhorse -- note that
`llama-3.3-70b-versatile` / `llama-3.1-8b-instant` are now
Enterprise-only); see https://console.groq.com/docs/models for other
current options. Two self-throttle knobs keep a busy voice call out of
429 territory: `GROQ_RATE_LIMIT_RPM` (default 30) spaces outgoing
requests, and `GROQ_TPM_LIMIT` (default 8000, the free tier for
gpt-oss-120b) drives a rolling 60s tokens-per-minute gate that holds
or drops requests that would cross the limit. `GROQ_RETRY_MAX_WAIT`
(default 3.0s) is the longest a rate-limit backoff may block before
the client gives up and returns the fallback -- on a live call a reply
arriving 20s late is worse than no reply, and the voice pipeline stays
silent on fallback instead of speaking it. `GROQ_REASONING_EFFORT`
(default `low`) controls gpt-oss's hidden reasoning phase: reasoning
tokens are spent *before* visible content and count against both
`max_tokens` and TPM, so at the default `medium` effort a short voice
reply could be emptied out entirely (empty content = silent voice).
Only sent for `openai/gpt-oss-*` models; leave empty to disable.

Unlike Shapes, Groq is a plain instruct model with no personality
dashboard, so `INJECT_FULL_CHARACTER_PROMPT` defaults to `true` for
this backend -- Alice's full lore/identity/style-example block (from
`character/data/alice/`) is built and sent on every request.

## Voice Capabilities (v2.3)

Alice can **listen and speak in Discord voice calls** with conversation-aware
interaction — she knows who's speaking, when to respond, and when to stay quiet.

Two TTS engines behind one switch (`VOICE_TTS_ENGINE`):
- **`sovits`** (default): local GPT-SoVITS server speaking in Alice's
  fine-tuned timbre (no RVC stage); the bot auto-starts/health-checks
  the server and stays silent-but-muted until it's proven usable.
- **`edge`**: cloud Edge-TTS + RVC voice conversion (original pipeline,
  also the automatic fallback if sovits can't start).

### Features
- **Speech-to-Text**: Moonshine (fixed-language, no detection) for fast transcription, with `faster-whisper` fallback + optional auto-detection
- **Text-to-Speech**: GPT-SoVITS (local fine-tuned Alice model, auto-started) with silent Edge-TTS fallback + optional RVC voice conversion
- **Voice Conversion (RVC)**: Neural voice cloning trained on Alice's voicelines
- **Speaker Diarization**: `pyannote.audio` identifies who's speaking
- **Silero VAD**: Neural voice activity detection (98% accuracy, 12ms latency)
- **Streaming TTS**: Sentence-by-sentence playback — first audio plays while remaining sentences are still being synthesized (52% faster time-to-first-audio)
- **Muted Until Ready**: `/join` connects self-muted if the voice engine is still warming up, then auto-unmutes itself once TTS is proven usable (replies/backchannels are dropped silently during warmup)
- **Quiet Text, Clean Voice**: `...` in text denotes quiet/trailing-off moments (stammers removed); any stammer fragment reaching TTS is stripped so the engine never spells out letter names — her tone in call already carries the shyness
- **Conversation-Aware Response**: I1/I2/S1/S2 framework from research — responds when directly addressed, stays silent when others are chatting
- **Turn Detection**: Sample-based timing for accurate speech completion
- **Backchannels**: Brief acknowledgments (mm, uh-huh / うん, ううん) during natural pauses
- **Barge-In**: Owner can interrupt Alice's response
- **Voice receive resilience**: `voice/dave_patch.py` wraps discord-ext-voice-recv methods (rather than editing site-packages) to decrypt Discord's DAVE (E2EE) incoming audio and survive corrupt packets — pip upgrades don't undo it
- **Language Support**: Fixed-language STT by default (`en`, detection off to save time/resources); `VOICE_STT_LANGUAGE=auto` re-enables detection via faster-whisper, `ja` selects the Japanese Moonshine model
- **Japanese Accent**: On the edge engine, a Japanese TTS voice + RVC model gives Alice a natural Japanese accent when speaking English — lore-accurate for a Japanese character (the sovits engine speaks English in Alice's own fine-tuned timbre instead)
- **STT Evaluation**: `VOICE_STT_CAPTURE=true` saves raw voice clips + sidecars to `stt_eval/clips/`; `python manage.py eval-stt` scores candidate engines/preprocessing on your own speech (see "STT Evaluation" below). Off by default.
- **Hallucination filter**: transcripts that are near-verbatim loops of
  prompt phrases (e.g. "Alice, how are you doing? Alice, how are you doing?")
  or silent impostors are dropped before they reach the AI.

### STT Evaluation
Accent robustness is measured against a **real recording, not a public benchmark**:
1. Set `VOICE_STT_CAPTURE=true` and talk to the bot — clips land in
   `stt_eval/clips/` (self-limits at `VOICE_STT_CAPTURE_LIMIT`, default 200).
2. `python manage.py eval-stt` generates `stt_eval/refs.csv` prefilled with
   machine transcripts. **Correct the refs by listening** — with accents,
   machine transcripts diverge most, so human references are mandatory.
3. Re-run `eval-stt`: it scores the candidate matrix (engines ×
   preprocessing) and writes `stt_eval/report.md` + `report.csv` with WER,
   p50/p95 latency, worst clips, and VRAM per candidate.
4. Pick the winner (lowest WER, tie-break latency) and set
   `VOICE_STT_ENGINE` / `VOICE_STT_MODEL` accordingly.

> **Current default**: `whisper-medium` (faster-whisper, `int8_float16`) —
> chosen via eval-stt on the owner's accented English (WER 0.32 vs 0.59 for
> moonshine-base). Re-run the eval anytime to recompare.

> **Mic quality**: Discord's client-side **Krisp** noise suppression
> (Voice settings → Noise Suppression) is a free mic-quality win on your
> end — no bot changes needed.

### Voice Pipeline
```
Discord Voice (Opus 48kHz stereo)
    → AliceVoiceSink (per-user buffering)
    → Silero VAD (speech/silence detection, 12ms)
    → Turn Detector (7 states: idle/single/multi/pause/lull/responding/barge_in)
    → faster-whisper STT (~1.2s, accent-robust)
    → Conversation Tracker (rolling context window)
    → Response Decision Engine (I1/I2/S1/S2 + owner priority)
    → AI Response (with conversation context + language instruction)
    → Sentence Splitter → Streaming TTS (GPT-SoVITS, sentence-by-sentence)
    → (fallback: Edge-TTS + RVC — only if GPT-SoVITS is unavailable)
    → StreamingAudioSource → Discord Voice
```

### Conversation-Aware Interaction

Alice uses a research-backed decision framework:

| Category | Trigger | Alice's Response |
|----------|---------|-----------------|
| **I1: Direct Address** | "Alice, what do you think?" | Always respond (CRITICAL for owner) |
| **I2: Contextual** | Conversation lull (4s silence) | 30% chance to join (shy personality) |
| **S1: No Reference** | Two others chatting | Stay silent |
| **S2: Third-Person** | "Alice is nice" (not addressed) | Soft clarification (*"Hmm? ... was I being talked about?"*) — see "Name-Mention Awareness" below |

Additional behaviors:
- **Owner priority**: Always responds to owner mentions
- **Backchannels**: Brief うん/ううん during natural pauses
- **Barge-in**: Owner can interrupt with "Alice!" during response
- **Cooldown**: 2s minimum between replies

### Name-Mention Awareness

By default Alice now responds when her name is mentioned, even if she isn't
directly addressed (the S2 case above). Instead of staying silent, she replies
with a short, tentative clarification — as if she thought she heard herself
called: *"Hmm? ... did I hear my name?"* / *"えっ？……あたしの名前を呼んだ？"*.
This makes her feel more responsive without jumping into a conversation.

- `VOICE_NAME_MENTION_RESPONSE=soft` (default): respond with a short
  clarification phrase
- `VOICE_NAME_MENTION_RESPONSE=skip`: original behavior — stay silent on
  S2 mentions

The clarifications come from a static EN+JA phrase pool (`voice/soft_phrases.py`) —
no AI round-trip, so peeking in costs almost no latency.

### Diarization Mode

When enabled, each clip is analyzed by `pyannote` (non-blocking; ~1GB VRAM
while active) to count how many speakers were present. This matters in party
channels where several people talk over each other:

- `VOICE_DIARIZE_MODE=none` (default): disabled, zero overhead
- `VOICE_DIARIZE_MODE=detect`: non-blocking analysis + silence when a mixed
  clip only mentions Alice in third person (forced SKIP), plus gating of
  backchannels on mixed clips
- `VOICE_DIARIZE_MODE=address`: same as `detect` (kept for compatibility)

Stats appear in `/voice-status` under "Diarization" (speakers in the last
clip, multi-speaker clip count).

> Tip: keep `none` while gaming (pyannote competes for GPU), and enable
> `detect` to silence Alice on mixed-clip chatter.

### Voice Extraction Pipeline

Alice's voice datasets are prepared using:
1. YouTube download → pyannote diarization → Whisper transcription
2. Manual verification CLI with batch mode
3. Data augmentation (audiomentations): time stretch, pitch shift, compression
4. CLI generation tool for expanding with Edge-TTS + RVC
5. Denoise (UVR) → normalize → ASR-rebuilt labels → GPT-SoVITS fine-tune

**Weights** (last training run, both loaded by the live server):

(`voice/sovits.py`), health-probes it at boot (`voice/readiness.py`),

## Deploying to Kerit Cloud

With `AI_BACKEND=groq` (or `shapes`), inference happens off-host, so
the bot process itself is light enough for a small/free-tier plan -- it
just holds a Discord gateway connection and makes small HTTPS calls.

1. Create a Python server on Kerit Cloud's panel.
2. Upload the project (everything except `venv/`, `__pycache__/`, and
   `_legacy/` -- those aren't needed on the host) or connect it via git.
3. Set the startup command to `python main.py` (or whatever the panel's
   convention is -- check for a "startup file" field).
4. Set environment variables in the panel exactly as in your local
   `.env` (or upload `.env` directly if the panel supports it).
5. Install dependencies: `pip install -r requirements.txt`.
6. Start the server. `data/`, `logs/`, and `_legacy/` all live under
   the project folder, so they persist on Kerit's disk across restarts
   -- no external database needed.
7. Given the free tier's 2GB storage cap, `REDDIT_RAW_RETENTION_FILES`
   (default 20 per subreddit) keeps old raw dumps pruned automatically.
   Lower it if you're tight on space.

**For multi-bot or horizontal scaling:**
- Add a Redis instance (Kerit supports Redis addon)
- Set `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` in env
- Set `LOG_JSON=true` for structured logging
- Health checks available at `http://<host>:8080/healthz` and `/ready`

## What Changed from the Original Bot (and why)

- **Reddit fetching now actually exists.** The original had filtering/
  dedup/rotation but nothing that fetched raw dumps -- a leftover
  Chrome profile suggested manual browser scraping. `reddit/fetcher.py`
  now pulls from the PullPush archive (`api.pullpush.io`, no API key),
  because Reddit 403s unauthenticated JSON and ended self-serve API app
  creation in Nov 2025. `REDDIT_SOURCE=reddit` keeps the legacy
  direct `www.reddit.com` JSON path for networks where it still works;
  either way the dump format is Reddit's own listing shape, so the
  updater doesn't care which source ran.
- **Memory now survives a restart.** The SQLite database was
  faithfully logging every message, but the actual memory used in
  conversations (`MemoryGraph`) lived only in RAM and reset on every
  restart. `MemoryGraph.hydrate()` now rebuilds it from SQLite at
  startup.
- **Memory persists across restarts for Reddit rotation too** --
  `rotation_state.json` remembers which posts you've already been
  shown.
- **Emotion state is now per-user**, not shared globally across every
  Discord user. Given everything else (memory, relationships, chat
  history) was already tracked per-user, a single shared mood looked
  like an oversight rather than an intentional design choice -- flagging
  this explicitly in case you'd rather it be shared.
- **Dead code removed** (not ported forward, but still in `_legacy/`
  if you want it back): `persona_compiler.py`, `identity_firewall.py`,
  `intent_classifier.py`, most of `memory.py`'s retrieval functions,
  `group_intelligence.py`'s attention tracking (computed every message
  but its output was always discarded before reaching the prompt), and
  the second `phi3:mini` routing model (replaced with the same cheap
  heuristic it was gated behind anyway).
- **Blocking SQLite calls no longer stall the event loop** -- they're
  wrapped in `asyncio.to_thread` at every call site.
- **Hardcoded values became data.** Alice's identity keywords, GIF
  intent triggers, and the maintainer-specific relationship mapping all moved
  from Python string literals into JSON files under `character/data/`
  and `social/data/`.
- **Added a Groq backend (`ai/groq_client.py`).** Shapes.inc deprecated
  third-party API access after this bot was first built around it, so
  Groq -- also OpenAI-compatible, cloud-hosted, no GPU needed -- is now
  the default `AI_BACKEND`. Swapping backends is still a one-file,
  one-env-var change; see "AI backends" above.

## Security Note

This project's original `.env` held a **live Discord bot token** and provider API keys in
plaintext, and they passed through the conversation that produced this rebuild.

**None of them appear in this repository or anywhere in its history.** The published
copy was assembled from a filtered staging directory before the first commit: `.env`,
the nested `Gemini-Voice-Splitter/.env`, every credential, all voice-model assets and
training pipelines, private chat logs, real Discord user IDs, and the maintainer's
identity were all excluded. What remains here is source code.

A build of this project therefore starts with **no usable credentials at all** — there
is no `.env` to inherit. Anyone setting it up must supply their own Discord bot token
and provider keys, and should rotate them if they reuse any value from elsewhere:

- **Discord bot token.** `Discord Developer Portal -> your application -> Bot ->
  Reset Token` invalidates the previous one immediately, with no grace period. A bot
  token *is* the bot's account, so this matters more than the API keys below.
- **Provider keys.** Revoke anything reused from the original build: Groq, Hugging Face,
  Gemini, fish.audio, and Shapes.inc (already deprecated upstream).

The OpenAI key referenced in earlier revisions of this note is no longer used by the
project; it now runs on Groq through the OpenAI-compatible API.

If you are reading this because you forked it: the same discipline applies to your own
`.env`. Do not commit it, and rotate anything that ever crossed a chat window — a
hosted AI assistant is a third party, and anything you paste is in their logs.
